# قائمة اختبار القبول — المرحلة الثامنة

استخدم هذه القائمة للتحقق من اكتمال كل متطلب قبل الإطلاق النهائي.
كل بند يجب أن يُختبر فعليًا وتُوضع علامة ✓ أو ✗.

## 1. النظام القائم (التوافق الرجعي)

### الصفحات الأصلية
- [ ] index.html يُوجّه بشكل صحيح بعد التحقق
- [ ] login.html يعمل (بريد/كلمة مرور + Google + استعادة)
- [ ] dashboard.html يُحمّل بدون أخطاء
- [ ] customers.html يعرض العملاء القائمين
- [ ] employees.html يعرض الموظفين القائمين
- [ ] services.html يعرض الخدمات القائمة
- [ ] orders.html يعرض الطلبات القائمة
- [ ] payments.html يعرض المدفوعات القائمة
- [ ] invoices.html يعرض الفواتير القائمة
- [ ] treasury.html يعرض معاملات الخزينة القائمة
- [ ] reports.html يعرض التقارير
- [ ] settings.html يفتح للمدير

### البيانات القائمة
- [ ] جميع العملاء القائمين قابلون للوصول
- [ ] جميع الموظفين القائمين قابلون للوصول

## 3. الصلاحيات

### عزل الموظف
- [ ] الموظف لا يصل لبيانات موظفين آخرين
- [ ] الموظف لا يرى لوحة التحكم المالية للشركة
- [ ] الموظف لا يغيّر صلاحياته بنفسه
- [ ] الموظف لا يغيّر راتبه أو عمولته
- [ ] الموظف لا يصل لإعدادات النظام

### عزل العميل
- [ ] العميل لا يصل لبيانات عملاء آخرين
- [ ] العميل لا يرى معلومات الموظفين الداخلية
- [ ] العميل لا يصل للوحة الإدارة
- [ ] العميل يرى طلباته فقط
- [ ] العميل يرى مدفوعاته فقط

### الصلاحيات الدقيقة
- [ ] موظف بدون canViewCustomers لا يرى صفحة العملاء
- [ ] موظف بدون canCreateOrders لا يُنشئ طلبات
- [ ] موظف بدون canViewTreasury لا يرى الخزينة
- [ ] القائمة الجانبية تتكيف مع الصلاحيات
- [ ] أزرار الإجراءات تختفي بدون الصلاحية
- [ ] المحاولات المباشرة (URL) تُرفض بالقواعد

## 4. الدقة المالية

### المدفوعات
- [ ] المدفوعات المعلّقة (pending) لا تُحتسب في النقد المؤكد
- [ ] المدفوعات المعتمدة (approved) تُحتسب مرة واحدة فقط
- [ ] رفض دفعة لا يتأثر به رصيد العميل
- [ ] اعتماد دفعة يُحدّث: حالة الدفعة + رصيد العميل + إيداع الخزينة (ذرّي)
- [ ] حذف دفعة يُعيد تحديث رصيد العميل

### المحاسبة
- [ ] الإيراد المحقق = مجموع الطلبات غير الملغاة
- [ ] النقد المحصّل = مجموع المدفوعات المعتمدة فقط
- [ ] الذمم المدينة = الإيراد - النقد
- [ ] صافي الربح = الإيراد - المصروفات - التعويضات
- [ ] هامش الربح تُحسب بشكل متّسق عبر dashboard وreports وP&L
- [ ] dashboard.html وprofit-loss.html يعرضان نفس الأرقام

### الخزينة
- [ ] رصيد الخزينة = إيداعات - سحوبات + تحويلات
- [ ] إيداع مرتبط بدفعة يتطلّب أن تكون معتمدة
- [ ] لا تكرار في الإيداعات عند تحديث دفعة

## 5. سير العمل

### تسجيل العميل
- [ ] العميل يسجّل حسابًا من portal-login.html
- [ ] وثيقة customer تُنشأ مع uid = auth.uid
- [ ] العميل يُوجّه إلى portal-dashboard.html

### الطلبات
- [ ] العميل يرسل طلب خدمة من portal-orders.html
- [ ] الطلب يظهر في orders.html للمدير
- [ ] المدير يعتمد الطلب (approvalStatus → approved)
- [ ] العميل يرى شارة «معتمد» في بوابته
- [ ] المدير يعيّن موظفين متعددين
- [ ] الموظف يرى الطلب/المهمة في لوحته
- [ ] العميل يرى المراحل المرئية فقط

### المدفوعات
- [ ] العميل يرفع إثبات دفع من portal-payments.html
- [ ] الدفعة تُنشأ بحالة pending
- [ ] المدير يرى زر الاعتماد/الرفض
- [ ] الاعتماد يُحدّث الرصيد + يُنشئ إيداع خزينة
- [ ] العميل يرى الحالة المحدّثة

### المهام
- [ ] المدير ينشئ مهمة ويعيّن موظفين
- [ ] الموظف يرى المهمة في employee-dashboard.html
- [ ] الموظف يحدّث التقدّم (مراحل)
- [ ] الموظف يسلم للمراجعة (under_review)
- [ ] المدير يعتمد أو يرفض
- [ ] الاعتماد يُسجّل مستحق في employeeLedger
