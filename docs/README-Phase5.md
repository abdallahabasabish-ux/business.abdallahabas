# المرحلة الخامسة — المدفوعات والمحاسبة المتقدمة

## التركيب السريع

### 1. انسخ الملفات الجديدة

```
من: phase5-accounting/new-files/
إلى: مشروعك/

  expenses.html               ← صفحة المصروفات
  employee-ledger.html         ← صفحة مستحقات الموظفين
  payment-methods.html         ← صفحة طرق الدفع
  profit-loss.html             ← تقرير الأرباح والخسائر

من: phase5-accounting/new-files/assets/js/
إلى: مشروعك/assets/js/

  accounting.js                ← وحدة الحسابات الموحّدة (مصدر الحقيقة)

من: phase5-accounting/new-files/assets/js/pages/
إلى: مشروعك/assets/js/pages/

  expenses.js                  ← إدارة المصروفات
  employee-ledger.js           ← دفتر أستاذ الموظفين
  payment-methods.js           ← طرق الدفع
  profit-loss.js               ← تقرير P&L
```

### 2. استبدل الملفات المُحدَّثة

```
من: phase5-accounting/updated-files/assets/js/
إلى: مشروعك/assets/js/

  sidebar.js                   ← قائمة جانبية مع عناصر جديدة
  dashboard.js                 ← أرقام مالية دقيقة + ملخص مباشر
```

### 3. اختبار سريع

1. سجّل دخول كمدير → القائمة الجانبية تعرض: المصروفات، مستحقات الموظفين، الأرباح والخسائر، طرق الدفع
2. افتح `payment-methods.html` → أضف طرق دفع (تحويل بنكي، InstaPay، Vodafone Cash)
3. افتح `expenses.html` → سجّل مصروفًا (مثلاً: إيجار، $500، تشغيلية)
4. افتح `employee-ledger.html` → أضف مكافأة لموظف، أو سجّل دفعة
5. افتح `profit-loss.html` → سترى تقريرًا كاملاً:
   - الإيراد المحقق vs النقد المحصّل vs ذمم مدينة
   - المصروفات حسب الفئة مع رسم بياني
   - تعويضات الموظفين (أرباح + مكافآت - خصومات - مدفوعات)
   - صافي الربح وهامش الربح
6. افتح `dashboard.html` → ستجد «الملخص المالي المباشر» في الأسفل مع 6 بطاقات دقيقة

## الميزات الجديدة

### 1. وحدة الحسابات الموحّدة (accounting.js)
- **مصدر الحقيقة الوحيد**: كل من dashboard وreports وprofit-loss يستخدم نفس الدوال
- **الدقة المالية**: الإيراد = الطلبات غير الملغاة، النقد = المدفوعات المعتمدة فقط
- **9 حسابات**: إيراد محقق، نقد محصّل، ذمم مدينة، مصروفات، تعويضات، خزينة، أرباح، هامش
- **مقارنة فترات**: حساب التغيير % بين فترتين

### 2. إدارة المصروفات (expenses.html)
- CRUD كامل مع 9 فئات (تشغيلية، تسويق، برمجيات، استضافة، رواتب، مدفوعات مهام، مرافق، إيجار، أخرى)
- إحصائيات: إجمالي، هذا الشهر، عدد، متوسط
- فلترة بالفئة والبحث
- ربط بالطلبات (اختياري)
- 5 طرق دفع (كاش، بنكي، بطاقة، إلكتروني، أخرى)

### 3. دفتر أستاذ الموظفين (employee-ledger.html)
- 4 أنواع قيود: ربح مهمة، مكافأة، خصم، دفعة مدفوعة
- **تسجيل دفعة**: زر يحسب المستحق للموظف ويسجّل الدفعة تلقائيًا
- إحصائيات: أرباح، مكافآت، خصومات، مدفوعات، صافي المستحق
- فلترة بالموظف والنوع
- ربط بالمهام والطلبات

### 4. طرق الدفع (payment-methods.html)
- CRUD بسيط لطرق الدفع
- الحقول: اسم، مستفيد، معرّف، تعليمات، نشط/معطّل
- **متكامل مع بوابة العميل**: portal-payments.js (من المرحلة 3) يقرأ هذه الطرق تلقائيًا
- لا حاجة لترميز بيانات الدفع في الشيفرة

### 5. تقرير الأرباح والخسائر (profit-loss.html)
- فلاتر زمنية: 7/30/90/365 يوم، مخصص، الكل
- 4 أقسام رئيسية: الإيرادات، المصروفات، الموظفون، الخزينة
- خلاصة: صافي الربح وهامش الربح
- رسم بياني دائري لتوزيع المصروفات
- مقارنة مع الفترة السابقة (تغيير %)

### 6. لوحة تحكم محدّثة (dashboard.js)
- `statPayments` يعرض **النقد المحصّل** (المعتمد فقط) بدل الإجمالي
- `statRevenue` يعرض **الإيراد المحقق** (بدون الملغاة)
- قسم جديد «الملخص المالي المباشر» بـ 6 بطاقات: إيراد، نقد، ذمم مدينة، مصروفات، مستحقات موظفين، صافي الربح

## الدقة المالية المُعالَجة

| المشكلة السابقة | الحل |
|----------------|------|
| المدفوعات المعلّقة تُحتسب كإيراد | فقط المعتمدة (status=approved) تُحتسب |
| لا تمييز بين الإيراد والنقد | إيراد محقق ≠ نقد محصّل ≠ ذمم مدينة |
| لا حساب لصافي الربح | صافي = إيراد - مصروفات - تعويضات |
| مصادر متعددة للأرقام | accounting.js = مصدر واحد موحّد |
| مصروفات غير مسجّلة | expenses.html كامل |
| مستحقات الموظفين غير مدارة | employee-ledger.html كامل |
| طرق دفع مدمجة في الشيفرة | payment-methods.html قابل للتهيئة |
